## Anatomy

The wheel renders two synchronized layers. `api.items` is the rotating 3D wheel. `api.highlightItems` is the selected
row, drawn inside the clipped highlight.

> Pass a unique `id` to the machine so generated element ids stay stable.

## Collection

Every item needs a `label` and a `value`, and can be `disabled`.

```ts
const collection = wheelPicker.collection({
  items: [
    { label: "React", value: "react" },
    { label: "Angular", value: "angular", disabled: true },
  ],
})
```

## Controlled value

Use `value` and `onValueChange` to own the state. `api.setValue` jumps to a value; `api.scrollToIndex` animates to it.

```ts
const service = useMachine(wheelPicker.machine, {
  collection,
  value,
  onValueChange: (details) => setValue(details.value),
})
```

## Scroll events

`onScrollChange` fires while the centered item changes. `onValueChangeEnd` fires once the wheel settles.

```ts
const service = useMachine(wheelPicker.machine, {
  collection,
  onScrollChange: (details) => console.log("centered:", details.value),
  onValueChangeEnd: (details) => console.log("settled:", details.value),
})
```

## Scroll feel

`dragSensitivity` sets how far the wheel coasts after a drag, `scrollSensitivity` how fast it steps. `optionItemHeight`
must match the rendered item height.

```ts
const service = useMachine(wheelPicker.machine, {
  collection,
  infinite: true,
  dragSensitivity: 5,
  scrollSensitivity: 5,
  optionItemHeight: 30,
})
```

## Forms

Set `name` and render the hidden select with every collection item. `disabled` blocks interaction and submission;
`readOnly` keeps the control focusable.

## Styling

Every part has `data-scope="wheel-picker"` and a `data-part` attribute. The machine sets the structural styles (3D
transforms, positions) inline, so your CSS only handles the look. The control exposes `data-focus`,
`data-focus-visible`, `data-dragging`, `data-scrolling`, `data-disabled`, `data-readonly` and `data-invalid`. Items
expose `data-selected` and `data-disabled`.
